# DinQorAI 后端任务清单

## 目标

将现有 Spring Boot 后端逐步整理为业务边界清晰的模块化单体，并支持以下完整链路：

```text
内容计划 -> 定时触发 -> AI 生成 -> 质量检查/审核 -> 本站及多平台发布 -> 结果追踪
```

重组期间保持现有 HTTP API、数据库数据和部署方式兼容，不提前拆分微服务。

## 横向工程任务

### 架构约束

- [ ] 新业务禁止直接加入全局 `controller/service/entity/mapper`
- [ ] Controller 和 MCP 只调用 Application Use Case
- [ ] 业务模块不得直接解析 JWT
- [ ] 业务模块不得直接读取其他模块的数据表
- [ ] 外部 HTTP 调用不得位于数据库事务中
- [ ] 为跨模块依赖建立清晰接口
- [ ] 考虑增加 ArchUnit 自动检查包依赖方向

### 数据库

- [ ] 所有表和字段包含中文 `COMMENT`
- [ ] 所有已有表修改提供 migration SQL
- [ ] 基线 schema 与 migration 保持同步
- [ ] 为计划扫描、任务领取和发布幂等增加索引
- [ ] 所有时间字段明确 UTC/时区语义
- [ ] 发布记录和执行记录保留审计信息

### 安全

- [ ] 密码改为 BCrypt/Argon2 哈希，禁止明文存储
- [ ] 验证码增加发送频率限制
- [ ] 登录增加失败次数限制
- [ ] 审查 AuthInterceptor 的默认放行策略
- [ ] 私有 API 使用显式保护规则
- [ ] 发布凭据按用户和平台隔离
- [ ] 敏感配置只使用环境变量或本地配置
- [ ] 日志脱敏
- [ ] 增加权限越权测试

### 可观测性

- [ ] 为计划、Agent 和发布生成统一 trace ID
- [ ] 记录阶段耗时
- [ ] 记录模型调用和平台调用结果
- [ ] 增加任务成功率和失败原因统计
- [ ] 增加卡死任务和凭据失效告警

### 测试规范

- [ ] 每个新业务模块建立对应测试包
