# 套餐与永久积分

Core 独占订阅权益与积分账本；Payment 独占收款订单，只通过服务鉴权契约查询订阅和发放权益。

| 套餐 | 全价 | 本次赠送积分 | 有效期 |
| --- | --- | --- | --- |
| PLUS | ¥2 | 20 | 30 天 |
| PRO | ¥4 | 50 | 30 天 |
| ULTRA | ¥10 | 150 | 30 天 |

有效期内只能升级。升级支付新套餐全价，获得新套餐完整积分，从发放成功起重新计算 30 天。旧套餐剩余积分保留原到期日，不能因升级延长。每人只有一个当前套餐；积分可以有多个各自到期的批次。

额外积分支持最多三个可配置道具卡，按 ¥1 = 10 积分定价，例如 10 积分 / ¥1、50 积分 / ¥5、100 积分 / ¥10。下单份数为 1–1000 的整数，且单笔总积分不得超过 10000。仅下单时订阅有效的用户可以购买；支付期间订阅到期不影响已支付订单发货。购买积分永久有效，无订阅也可继续消费。消费先扣最早到期的套餐积分，再扣永久积分。历史余额保留为永久积分，不追溯重发历史订阅奖励。

## 发布顺序

1. 备份 Core 与 Payment D1；应用 Core `0010_subscription_points.sql` 和 Payment `0003_points_orders.sql`、`0004_points_products.sql`。迁移只新增批次、视图、订单字段并替换权益/账本触发器，不改写历史余额。
2. 发布 Core、Payment、Gateway 和管理台。发布前核对现有绑定、独立模块与 Durable Object 迁移，避免覆盖线上专有模块。
3. 微信后台的旧 PLUS ¥10 / PRO ¥20 / ULTRA ¥30 与新价格不一致。修改并发布对应商品，或创建新商品并使用新 ID。另发布三个永久积分商品，价格与本地积分卡配置对应。
4. 管理台微信配置填写 PLUS/PRO/ULTRA 的商品 ID、价格（200/400/1000 分）、30 天，以及新增的永久积分商品配置（管理台表单后续接入，现可通过管理员接口配置）。服务端拒绝错误价格、期限和重复 ID。目录校验只验证本地配置；微信后台是否同步必须另行核对。
   若启用网页支付宝支付，生产 `ALIPAY_PRODUCTS` 也须改为同样的价格和 30 天；旧订单仍按保存的金额和期限核验与发货。
5. 保留已配置的验签发货通知和查单补发流程。上传小程序后，在已发布商品上验证小额真实支付、回调、查单、到账和余额拆分；本地自动化测试不实际扣款。

## 一致性

积分单位为毫积分（1 积分 = 1000）。套餐发放事件和批次在同一 D1 事务内写入；重复支付事件不重发。消费与批次扣减由同一插入触发器执行。查询余额实时排除过期批次；账本、钱包和后续写操作会幂等结算过期记录，不依赖定时任务。账号合并迁移批次归属，保留原有效期。

并发或延迟支付导致同级/低级权益与当前订阅冲突时，Core 拒绝重复订阅或降级，Payment 保持未完成状态并可重试，不返回虚假发货成功。此类已付款冲突需人工查单与退款处理。

## 积分卡配置接口

管理员 GET/PUT `/api/admin/virtual-pay-settings` 新增 `pointsProducts` 数组；PUT 同时保留原来的 enabled、offerId、appKey 和 plus/pro/ultra 字段。AppKey 留空保留现有密钥。示例数组：

```json
[
  {"productId":"POINTS_10","name":"10积分卡","priceCents":100,"points":10,"enabled":true},
  {"productId":"POINTS_50","name":"50积分卡","priceCents":500,"points":50,"enabled":true},
  {"productId":"POINTS_100","name":"100积分卡","priceCents":1000,"points":100,"enabled":true}
]
```

价格单位为分。ID 限英文、数字、下划线且不超过 20 位，名称不超过 20 字，积分为 10 的正整数倍且不超过 10000；所有卡（包括停用卡）与套餐 ID 不得重复。`enabled:false` 隐藏该卡并禁止新下单。省略数组保留现有配置，`[]` 停用全部积分卡。未设置新数组时兼容旧 `pointsProductId`（每份 10 积分 / ¥1）；设置后新数组优先，旧管理端更新单商品字段不会覆盖新卡。

公开 GET `/api/virtual-pay/products` 仅返回启用商品，以 `kind:"points"` 区分积分卡。POST `/api/virtual-pay/orders` 继续只接收 productId、loginCode、quantity，价格和积分从服务端配置读取并签名；客户端传入价格或积分无效。下单后变更、停用或删除配置不影响原订单快照发放。该配置属于道具直购、自有积分账本，不使用微信代币充值。
