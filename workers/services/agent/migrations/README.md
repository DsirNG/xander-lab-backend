Agent owns conversation, message, and event rows in its D1 database. User IDs are
opaque references from Core; this schema deliberately has no foreign key to
Core's D1. Local article/file bytes stay in OSS and are represented by
attachment metadata only.

`0001_agent_conversations.sql` creates conversation and message storage;
`0002_agent_events.sql` adds the replayable SSE event log;
`0003_agent_skills.sql` adds immutable, user-owned Skill versions;
`0004_agent_tool_approvals.sql` adds the durable tool invocation journal and
owner approval snapshots; and `0005_agent_memory.sql` adds owner-scoped,
bounded long-term memory. `0006_agent_attachments.sql` stores owner-scoped
OSS object metadata. `0007_agent_mcp_servers.sql` adds owner-scoped outbound MCP
server settings, encrypted request-header metadata, and a bounded cached tool
catalog. `0008_agent_attachment_media.sql` links uploaded image attachments to
their Content-owned media-library records. Apply migrations with `pnpm dev`
locally or Wrangler against the Agent database in production.

Agent uploads object bytes to `agent-attachments/<userId>/<uuid>.<extension>`
in Aliyun OSS and stores only metadata in D1. The upload response contains a
10-minute V4 signed read URL. Message turns accept attachment IDs and resolve
them against the authenticated owner before storage and model submission. Set
`ALIYUN_OSS_ENDPOINT`, `ALIYUN_OSS_BUCKET`, `ALIYUN_OSS_REGION`,
`ALIYUN_OSS_ACCESS_KEY_ID`, and `ALIYUN_OSS_ACCESS_KEY_SECRET` for uploads.
Image uploads also call Content Automation's authenticated HTTPS
`/internal/content/media/upload-image` contract, which stores the image in the
Content OSS namespace and records owner-scoped metadata in Content D1. Agent D1
stores the returned asset ID. If the Agent metadata write fails, the service
best-effort deletes the Content asset and the Agent OSS object.

The Worker can execute text turns, replay progress, load active Skill prompts,
and expose the registered `publish_post` tool only when an active user Skill
selects it. A model call records a durable approval request before any
publication side effect; owner decisions are persisted in D1 and the call is
made through Content Automation only after approval. Ambiguous Content results
are recorded as `UNKNOWN` rather than automatically retried. Text turns precheck
Core balance and submit provider-reported usage. `remember` and `recall_memory`
use Agent D1, inject relevant owner memories into later model context, and keep
each user's records isolated. Chat Completions forwards image attachments;
Responses endpoints receive images and documents through legacy-compatible
input blocks. Outbound MCP servers are owner-scoped (platform configurations
belong to owner 0), use AES-GCM encrypted headers, reject non-HTTPS/private
endpoints and redirects, and expose a bounded cached tool catalog. Every remote
MCP invocation requires owner approval; uncertain outcomes are recorded as
`UNKNOWN` and never retried. Enable with `AGENT_MCP_CLIENT_ENABLED=true` and a
stable Base64 32-byte `AGENT_MCP_CREDENTIAL_ENCRYPTION_KEY`. Uploaded image
attachments and `image_generate` results register with the Content media
library. `image_generate` reads the `blog_agent_image` feature candidates from
Core, requires provider usage for Core billing, and saves generated bytes in
Content OSS. `delegate_subtask` allows bounded read-only child calls and bills
each model call with an independent idempotency key. `/ws/agent` replays D1
events over WebSocket. Responses API models receive document file blocks; local
document extraction/OCR is not implemented. `waitUntil` allows a streamed run
to continue after disconnect while its Worker invocation remains alive; a run
stopped by runtime termination is not automatically requeued.
